# feat(export): write the variance strings and the legend row in export_crosstab()

**Date**: 2026-11-20
**Branch**: feature/crosstab-variance-strings

## Changes

Ticket 04 of `plans/tickets/export-metadata/README.md`. Under
`variance = "se"` or `"ci"`, each crosstab estimate cell now shows the
standard error or the interval in parentheses, with one `%` per number. The
new argument `variance_display` puts that value on a second line of the cell
(`"cell"`, the default) or on its own row under the estimate (`"row"`). A
legend row under the question title says what the parentheses hold. The
sheet makes room for the value (spec 3.12, 3.16).

### `R/export-crosstab.R`

- New argument `variance_display = c("cell", "row")`, after `variance` and
  before `conf_level`. It is resolved with `match.arg()`, as `layout`,
  `withheld_note` and `sample_size_display` are. New `@param` entry; the
  `@param variance` entry now says what each value shows.
- The data column width is `15 + 2 * decimals` under `variance = "ci"` and 12
  otherwise. It is set where the fixed widths were already set, from the
  arguments only. Column B of a stacked sheet with a battery already takes
  the larger of 20 and that width, so XB-14 needed no other code.
- `.render_block_preamble()` takes `legend` after `base_note` and writes it
  as row 3 of spec 3.16, in the italic merged style of the base note. The
  comment that said the legend "comes in a later change" is gone.
- Each of the three render routes calls `.fmt_variance()` once per cell, so
  `grep -n "fmt_variance" R/export-crosstab.R` shows three call sites, one
  per route. Each route also sets the wrap and the 30-point height of its
  estimate rows. Under `"row"` each estimate row is followed by its variance
  row, with the label columns blank.
- New helpers, below the exported function:
  - `.col_has_rows()`: the whole-column test of gap 17. `.fmt_pct_cell()`
    now calls it, and the routes pass it to `.fmt_variance()`.
  - `.rows_per_estimate()`: 2 under `variance` set and `"row"`, else 1.
  - `.write_estimate_cell()`: writes the estimate alone when there is no
    variance string; under `"cell"` a two-run rich text cell made with
    `openxlsx2::fmt_txt()`, the second run a line break and the variance
    string at 9 points in `#595959`; under `"row"` the variance string in
    the row below.
  - `.style_estimate_rows()`: under `variance` set and `"cell"`, wrap on for
    every data cell of the estimate rows and a fixed height of 30 points.
    Nothing is set in any other case.
  - `.build_variance_legend()`: the legend text, or `NULL`.
- `R/export-crosstab.R` still holds no inline `* 100`.

### `R/export-utils.R`

- `.fmt_variance()` has the gap 17 guard: it returns `""` when `rows` is
  empty or its `n` is 0. A `0%` cell with no row of its own reads `0%`
  alone, under both displays.
- Its comment said the exported function validates `variance`. It does not;
  `surveycore::get_freqs()` rejects any other value with
  `surveycore_error_invalid_variance_arg` before the workbook is built. The
  comment now says that.

### `man/export_crosstab.Rd`

- Regenerated by `devtools::document()`.

## Readings the spec leaves open

- The legend names the level through `.fmt_pct(conf_level, 4L, TRUE)`:
  0.95 reads `95%`, 0.9 reads `90%`, 0.975 reads `97.5%`. `.fmt_pct()` owns
  the conversion from a proportion to a percentage (spec 3.3), so the
  crosstab file gets no `* 100`, and the spec VIII grep still returns four
  lines.
- The estimate run of a two-line cell carries no font properties, so it
  takes the cell's own font. The second run sets the size and the colour
  only. Spec 3.21.3 (ticket 06) states both runs in full.
- A variance cell under `"row"` is plain text with no 9-point grey style.
  Spec 3.12 gives no style for it; spec 3.21.3 (ticket 06) adds one.
- The legend row reuses `.write_base_note()`, because spec 3.21.3 gives the
  base-note row and the legend row one style.
- An invalid `variance_display` aborts through `match.arg()`, with no
  surveyreports class, as the other three choice arguments do. The spec
  lists no error class for it.
- XH-17 "twice as many estimate rows" is read as: the rows below the
  sample-size rows under `"row"` are twice those under `"cell"` for the same
  call, and every second row is a variance row with blank label columns.
