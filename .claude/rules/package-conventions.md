# Package Conventions

---

## Quick Reference

| Decision | Choice |
|----------|--------|
| Import style | `::` everywhere; no `@importFrom` |
| `devtools::document()` | Before committing any file that changes roxygen2 content |
| `devtools::check()` | Before opening a PR |
| NAMESPACE edits | Never manual — 100% generated by `devtools::document()` |
| `R CMD check` | 0 errors, 0 warnings, ≤2 pre-approved notes |
| Export policy | All `report_*()` functions; no `.`-prefixed helpers; no re-exports |
| Internal function docs | `@keywords internal` + `@noRd` for complex helpers |
| `@returns` | Required on all exported functions — `@returns`, never `@return` |
| `@examples` | All runnable — no `\dontrun{}` |
| Version pinning | Minimum versions only (e.g., `cli (>= 3.6.0)`) |
| Function naming | `report_*` for exported; `.validate_*` for validators; `.` prefix for all internals |
| `@seealso` | Report functions link to each other and to underlying `surveycore::get_*()` |
| `@family` groups | `"frequency functions"` or `"descriptive statistics"` |
| Return values | Visible tibble; one row per variable (or variable × group) |
| `vars` argument | tidy-select; resolved to character vector early in the function body |
| Design validation | Always first — before tidy-select resolution |

## 1. Documentation (Roxygen2)

### `@param` verbosity

Write `@param` proportional to how non-obvious the argument is. Terse for simple
arguments; fuller for anything with constraints, `NULL` behavior, or interactions.

```r
#' @param design A survey design object created by [surveycore::as_survey()],
#'   [surveycore::as_survey_rep()], or [surveycore::as_survey_twophase()].
#'
#' @param vars <[`tidy-select`][tidyselect::language]> Variable(s) to tabulate.
#'   Use bare column names (`q1`), `c(q1, q2, q3)`, or tidyselect helpers like
#'   `starts_with("q")`. Cannot include design variables (weights, strata, PSU).
#'
#' @param group <[`tidy-select`][tidyselect::language]> Optional grouping
#'   column. When supplied, frequencies are computed separately within each
#'   level of the grouping variable. Default `NULL` (no grouping).
#'
#' @param ci Logical. Whether to compute confidence intervals. Default `TRUE`.
#'
#' @param ci_level Numeric scalar between 0 and 1. Confidence level for
#'   intervals. Default `0.95`.
```

### `@returns` for report functions

```r
#' @returns A tibble with one row per variable × response category, containing:
#'   - `variable`: the variable name
#'   - `label`: variable label (from surveycore metadata), or `NA`
#'   - `value`: the response category
#'   - `n`: unweighted count
#'   - `prop`: survey-weighted proportion
#'   - `prop_se`: standard error of the proportion
#'   - `prop_low`, `prop_high`: confidence interval bounds (if `ci = TRUE`)
#'   When `group` is supplied, an additional `group` column appears before
#'   `variable`.
```

### `@seealso` for report functions

```r
#' @seealso
#'   [report_means()] for continuous variables,
#'   [report_totals()] for estimated totals,
#'   [surveycore::get_freqs()] for the single-variable underlying function
```

### `@examples`: all runnable

Every example must run during `R CMD check`. Use a small inline dataset instead
of `\dontrun{}` for slow examples.

```r
#' @examples
#' df <- data.frame(
#'   q1 = c(1, 2, 1, 2, 1, 3),
#'   q2 = c("a", "b", "a", "a", "b", "b"),
#'   region = c("N", "N", "S", "S", "N", "S"),
#'   wt = c(1.2, 0.8, 1.1, 0.9, 1.0, 1.3)
#' )
#' d <- surveycore::as_survey(df, weights = wt)
#'
#' # Single variable
#' report_freqs(d, vars = q1)
#'
#' # Multiple variables
#' report_freqs(d, vars = c(q1, q2))
#'
#' # Grouped by region
#' report_freqs(d, vars = q1, group = region)
```

`air` does not reformat code inside roxygen comments — match `air` style manually:
2-space indent, 80-char width, `|>` for pipelines, one arg per line for long calls,
`#'` blank lines between logical blocks.

### `@family` groups

```r
#' @family frequency functions
report_freqs <- function(...) { ... }

#' @family descriptive statistics
report_means <- function(...) { ... }

#' @family descriptive statistics
report_totals <- function(...) { ... }
```

### Internal function documentation

```r
# One-liner — no roxygen needed
.get_col <- function(design, col) design@data[[col]]

# Complex helper — document but suppress .Rd
#' @keywords internal
#' @noRd
.validate_vars_exist <- function(design, vars) { ... }
```

## 2. Naming Conventions

| Category | Pattern | Example |
|----------|---------|---------|
| Report functions | `report_*` | `report_freqs()`, `report_means()`, `report_totals()` |
| Internal validators | `.validate_*` | `.validate_survey_object()`, `.validate_vars_exist()` |
| Internal helpers | `.` prefix | `.resolve_vars()`, `.build_result_frame()` |

## 3. NAMESPACE & Exports

Export all `report_*()` functions and user-facing utilities. Never export
`.`-prefixed helpers. S7 classes are defined in surveycore — do not re-export them.

Call all external functions with `::`. No `@importFrom` anywhere.

```r
#' @export
report_freqs <- function(...) { ... }

# Not exported (no @export tag)
.validate_survey_object <- function(design) { ... }
```

`NAMESPACE` is never manually edited — 100% generated by `devtools::document()`.

## 4. Key Implementation Patterns

### `vars` resolution

Resolve tidy-select arguments to character vectors early — before any computation
or validation. Never pass unresolved NSE expressions to surveycore.

```r
report_freqs <- function(design, vars, group = NULL, ...) {
  if (!S7::S7_inherits(design, surveycore::survey_base)) {
    cli::cli_abort(
      c(
        "x" = "{.arg design} must be a survey design object.",
        "i" = "Got class {.cls {class(design)}}.",
        "v" = "Use {.fn surveycore::as_survey} to create a design object."
      ),
      class = "surveyreports_error_not_survey_object"
    )
  }

  vars_resolved <- names(tidyselect::eval_select(
    rlang::enquo(vars),
    design@data
  ))
  group_resolved <- if (!is.null(rlang::enquo(group))) {
    names(tidyselect::eval_select(rlang::enquo(group), design@data))
  } else {
    NULL
  }

  .validate_vars_exist(design, vars_resolved)
  # ... rest of implementation ...
}
```

### Multi-variable pattern

Use `lapply()` + `dplyr::bind_rows()`. Do not grow a list manually or use `rbind`.

```r
results <- lapply(vars_resolved, function(var) {
  result <- surveycore::get_means(design, !!rlang::sym(var), ...)
  result$variable <- var
  result
})
dplyr::bind_rows(results)
```

## 5. Package Check Hygiene

**R CMD check targets:** 0 errors, 0 warnings, ≤2 notes.

Pre-approved notes (do not block merging):

| Note | Reason |
|------|--------|
| `no visible binding for global variable 'X'` | Universal in tidy packages — do NOT suppress with `utils::globalVariables()` |
| `checking CRAN incoming feasibility` | Informational only |

Run `devtools::document()` before committing any roxygen2 changes.
Run `devtools::check()` before opening any PR.

**Version pinning:** minimum bounds only — `cli (>= 3.6.0)`, `rlang (>= 1.1.0)`,
`surveycore (>= 0.8.2)`. No exact pins (`==`).

## 7. Pre-Commit Documentation Checklist

- [ ] `devtools::document()` run; `NAMESPACE` and `man/` files updated
- [ ] All exported functions have `@returns` describing the tibble structure
- [ ] All `@examples` are runnable and demonstrate multi-variable usage
- [ ] Internal helpers have `@keywords internal` + `@noRd` if needed
- [ ] `@family` tags are correct
- [ ] `report_*()` functions have `@seealso` linking to related functions
- [ ] No `@importFrom` tags anywhere — all external calls use `::`
- [ ] `R CMD check` passes with 0 errors, 0 warnings, ≤2 notes
- [ ] `plans/error-messages.md` updated if new error/warning classes added
