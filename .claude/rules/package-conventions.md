# Package Conventions

---

## Quick Reference

| Decision | Choice |
|----------|--------|
| Import style | `::` everywhere; no `@importFrom` |
| `devtools::document()` | Before committing any file that changes roxygen2 content |
| `devtools::check()` | Before opening a PR |
| NAMESPACE edits | Never manual — 100% generated by `devtools::document()` |
| `R CMD check` | 0 errors, 0 warnings, ≤2 pre-approved notes |
| Export policy | All `export_*()` and other user-facing functions; no `.`-prefixed helpers; no re-exports |
| Internal function docs | `@keywords internal` + `@noRd` for complex helpers |
| `@returns` | Required on all exported functions — `@returns`, never `@return` |
| `@examples` | All runnable — no `\dontrun{}` |
| Version pinning | Minimum versions only (e.g., `cli (>= 3.6.0)`) |
| Function naming | `export_*` for functions that write a file; a verb-noun name otherwise (`pool_pvals`); `.` prefix for all internals |
| `@seealso` | Export functions link to each other and to the underlying `surveycore::get_*()` |
| `@family` groups | Match the `_pkgdown.yml` sections: `"frequency functions"`, `"multiplicity correction"` |
| Return values | `export_*()` returns `invisible(file_name)`; computing functions return a visible tibble |
| `vars` argument | tidy-select; resolved to character vector early in the function body |
| Design validation | Always first — before tidy-select resolution (for functions that take a design) |

## 1. Documentation (Roxygen2)

### `@param` verbosity

Write `@param` proportional to how non-obvious the argument is. Terse for simple
arguments; fuller for anything with constraints, `NULL` behavior, or interactions.

The `@param design` entry names every accepted subclass and links each one to
its constructor. Take the list from `.claude/rules/testing.md`, **Cross-design
testing**; take the wording from
`.claude/standards/function-documentation.md`.

```r
#' @param design A survey design object created by one of the
#'   `surveycore::as_survey*()` constructors. `export_topline()` also accepts a
#'   [surveycore::as_survey_collection()] object for wave comparison.
#'
#' @param vars <[`tidy-select`][tidyselect::language]> Variable(s) to tabulate.
#'   Use bare column names (`q1`), `c(q1, q2, q3)`, or tidyselect helpers like
#'   `starts_with("q")`. Cannot include design variables (weights, strata, PSU).
#'
#' @param banner <[`tidy-select`][tidyselect::language]> The variable(s) whose
#'   levels become the column groups. Each level gets its own column of
#'   estimates.
#'
#' @param file_name Character scalar. The path of the `.xlsx` file to write.
#'   The function overwrites an existing file at this path.
#'
#' @param conf_level Numeric scalar between 0 and 1. Confidence level for
#'   intervals. Default `0.95`.
#'
#' @param decimals Integer scalar. Decimal places for percentages.
#'   Default `1L`.
#'
#' @param pub_type One of `"none"`, `"external"`, or `"internal"`. Sets the
#'   minimum effective n a subgroup needs before its column is written.
#'   `"none"` suppresses nothing. Default `"none"`.
```

### `@returns` for export functions

An export function writes a spreadsheet and returns the path, so say that and
describe the sheet rather than a tibble:

```r
#' @returns `invisible(file_name)` — the path supplied in `file_name`.
#'   Called for its side effect: it writes an `.xlsx` file with one sheet
#'   named `"Topline"`, holding one block per variable. Each block carries the
#'   question text, one row per response category, and a base note.
```

For a function that returns data, describe the columns:

```r
#' @returns An object of S3 class `c("survey_pooled_pvals", "tbl_df", "tbl",
#'   "data.frame")` with the columns of the pooled inputs plus:
#'   - `{id_col}`: which input element the row came from
#'   - `{new_col}`: the adjusted p-value
```

### `@seealso` for export functions

```r
#' @seealso [export_topline()] for topline (no banner) output,
#'   [surveycore::get_freqs()] for the underlying frequency function
```

### `@examples`: all runnable

Every example must run during `R CMD check`. Build a small inline dataset
rather than reaching for `\dontrun{}`.

A function that writes a file stays runnable by writing to `tempfile()`. Never
write to the working directory in an example — `R CMD check` forbids it:

```r
#' @examples
#' df <- data.frame(
#'   q1 = sample(c("Agree", "Neutral", "Disagree"), 200, replace = TRUE),
#'   group = sample(c("A", "B"), 200, replace = TRUE),
#'   wt = runif(200, 0.5, 1.5)
#' )
#' d <- surveycore::as_survey(df, weights = wt)
#'
#' out <- tempfile(fileext = ".xlsx")
#'
#' # Single variable
#' export_topline(d, vars = q1, file_name = out)
#'
#' # With a banner
#' export_crosstab(d, vars = q1, banner = group, file_name = out)
#'
#' file.remove(out)
```

**Current gap:** `export_topline()` and `export_crosstab()` still wrap their
examples in `\dontrun{}`. Convert both to the `tempfile()` pattern above.

`air` does not reformat code inside roxygen comments — match `air` style manually:
2-space indent, 80-char width, `|>` for pipelines, one arg per line for long calls,
`#'` blank lines between logical blocks.

### `@family` groups

Keep `@family` values aligned with the section titles in `_pkgdown.yml`, so
the reference index and the "See also" links agree:

```r
#' @family frequency functions
export_topline <- function(...) { ... }

#' @family frequency functions
export_crosstab <- function(...) { ... }

#' @family multiplicity correction
pool_pvals <- function(...) { ... }
```

### Internal function documentation

```r
# One-liner — no roxygen needed
.get_col <- function(design, col) design@data[[col]]

# Complex helper — document but suppress .Rd
#' @keywords internal
#' @noRd
.validate_vars_exist <- function(design, vars) { ... }
```

## 2. Naming Conventions

| Category | Pattern | Example |
|----------|---------|---------|
| Output functions | `export_*` | `export_topline()`, `export_crosstab()` |
| Helper functions | verb-noun | `pool_pvals()` |
| Internal validators | `.validate_*` | `.validate_export_inputs()`, `.validate_base_notes()` |
| Internal helpers | `.` prefix | `.build_freq_frame()`, `.compute_eff_n()`, `.render_topline_single()` |

`export_*` is reserved for functions that write a file. A function that returns
a value takes a plain verb-noun name.

## 3. NAMESPACE & Exports

Export all `export_*()` functions and user-facing helpers. Never export
`.`-prefixed helpers. S7 classes are defined in surveycore — do not re-export
them.

Register an S3 method with `@export` on the method, as
`print.survey_pooled_pvals()` does. `devtools::document()` turns that into an
`S3method()` line, not an `export()` line.

Call all external functions with `::`. No `@importFrom` anywhere.

```r
#' @export
export_topline <- function(...) { ... }

# Not exported (no @export tag)
.validate_export_inputs <- function(...) { ... }
```

`NAMESPACE` is never manually edited — 100% generated by `devtools::document()`.

## 4. Key Implementation Patterns

### `vars` resolution

Resolve tidy-select arguments to character vectors early — before any computation
or validation. Never pass unresolved NSE expressions to surveycore.

```r
export_topline <- function(design, vars, file_name, ...) {
  # 1. Design class check — before any tidy-select resolution
  if (
    !(S7::S7_inherits(design, surveycore::survey_base) ||
      S7::S7_inherits(design, surveycore::survey_collection))
  ) {
    cli::cli_abort(
      c(
        "x" = "{.arg design} must be a survey design object.",
        "i" = "Got class {.cls {class(design)}}.",
        "v" = "Use {.fn surveycore::as_survey} to create a design object."
      ),
      class = "surveyreports_error_not_survey_object"
    )
  }

  # 2. Resolve tidy-select to a character vector
  vars_resolved <- names(tidyselect::eval_select(
    rlang::enquo(vars),
    design@data
  ))

  # 3. Validate the resolved names
  .validate_export_inputs(design, vars_resolved, file_name)
  # ... rest of implementation ...
}
```

Never pass an unresolved NSE expression to surveycore.

### Multi-variable pattern

Two shapes, depending on what the function returns.

**A function that writes a file** loops the variables and threads the row
cursor through each block:

```r
wb <- .build_workbook()
current_row <- 1L

for (var in vars_resolved) {
  result <- .render_topline_single(wb, "Topline", frame, current_row, ...)
  wb <- result$wb
  current_row <- result$next_row + 1L
}

openxlsx2::wb_save(wb, file_name)
invisible(file_name)
```

**A function that returns data** uses `lapply()` plus
`dplyr::bind_rows()`. Do not grow a list by index and do not use `rbind()`:

```r
results <- lapply(vars_resolved, function(var) {
  result <- surveycore::get_freqs(design, !!rlang::sym(var))
  result$variable <- var
  result
})
dplyr::bind_rows(results)
```

### Question type dispatch

`vars` may hold single-response questions, select-all-that-apply blocks, and
batteries at once. Call `surveycore::classify_question_type()` and dispatch to
the matching render helper. A SATA or battery group renders once for the whole
group, not once per variable — track which group ids are done so a group is
not written twice.

## 5. Package Check Hygiene

**R CMD check targets:** 0 errors, 0 warnings, ≤2 notes.

Pre-approved notes (do not block merging):

| Note | Reason |
|------|--------|
| `no visible binding for global variable 'X'` | Universal in tidy packages — do NOT suppress with `utils::globalVariables()` |
| `checking CRAN incoming feasibility` | Informational only |

Run `devtools::document()` before committing any roxygen2 changes.
Run `devtools::check()` before opening any PR.

**Version pinning:** minimum bounds only. No exact pins (`==`).

## 6. Package Metadata

Read DESCRIPTION for its current contents. Two of its lines carry a reason the
file itself does not state, and both must stay:

- `LazyData: true` — the package ships four datasets, and they load lazily.
- `Remotes: JDenn0514/surveycore` — surveycore is not on CRAN. It belongs in
  `Imports`, never in `Suggests`. Moving it to `Suggests`, or dropping the
  `Remotes:` line, breaks installation.

Package-level documentation (`R/surveyreports-package.R`):

```r
#' surveyreports: Automate Survey Analysis and Helpers
#'
#' @description
#' surveyreports turns a survey design into finished reporting output. It
#' writes formatted spreadsheets over many variables at once, and supplies
#' helpers for the steps around them.
#'
#' @section Key Functions:
#' - [export_topline()] — a formatted topline workbook
#' - [export_crosstab()] — a formatted crosstab workbook with banner columns
#' - [pool_pvals()] — multiplicity correction across result families
#'
#' @keywords internal
"_PACKAGE"
```

### Datasets

The package ships `anes_2024`, `gss_2024`, `ns_wave1`, and `pew_jewish_2020`.
Each one is documented in `R/data.R` with `@format` describing its columns, and
each appears in the Datasets section of `_pkgdown.yml`. Use them in examples
where real labels, real factor levels, and real missingness are part of what
the example shows.

## 7. Pre-Commit Documentation Checklist

- [ ] `devtools::document()` run; `NAMESPACE` and `man/` files updated
- [ ] All exported functions have `@returns` — the written file for an
      `export_*()` function, the column list for one that returns data
- [ ] All `@examples` are runnable and demonstrate multi-variable usage
- [ ] Examples that write a file write to `tempfile()`, never the working
      directory
- [ ] Internal helpers have `@keywords internal` + `@noRd` if needed
- [ ] `@family` tags match the section titles in `_pkgdown.yml`
- [ ] Exported functions have `@seealso` linking to related functions
- [ ] `_pkgdown.yml` lists every new export
- [ ] No `@importFrom` tags anywhere — all external calls use `::`
- [ ] `R CMD check` passes with 0 errors, 0 warnings, ≤2 notes
- [ ] `plans/error-messages.md` updated if new error/warning classes added
